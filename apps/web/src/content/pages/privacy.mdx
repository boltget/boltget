title: Privacy

Boltget collects nothing about you by default. This page says exactly what each part does, in plain words. If that ever changes, it changes here first.

## This website

- No cookies, no analytics, no tracking scripts, no advertising.
- No third-party requests: fonts, images and scripts are served from boltget.app itself.
- Docs search runs in your browser on a prebuilt index. What you type is not sent anywhere.
- The site is static files on a hosting provider, which may keep standard request logs (IP address, time, page requested) for security and operations. Boltget does not use them to identify or track visitors. The site is hosted on Cloudflare Workers with static assets.
- Links to GitHub take you to GitHub, which has its own privacy policy.

## The command-line tool (v0.1)

- It connects only to the addresses you give it, the servers they redirect to, and the proxy you configure. It sends no telemetry and checks for no updates.
- Your download list lives on your own disk: `%LOCALAPPDATA%\Boltget` on Windows, `$XDG_DATA_HOME/boltget` on Linux. It holds each download's address, file name, progress and the settings you chose.
- `Authorization` headers, proxy passwords, `--cookie` values and `--user` credentials are never written to disk. For a cookie file, only its path is saved; the file is read again when you resume.
- Addresses in logs, JSON events and `boltget list` are shown with credentials removed, because signed links carry secrets.
- Finished files get the Windows Mark of the Web, like browser downloads; the address recorded there has its query string and credentials removed.

## The desktop app

- The Windows preview runs the download engine on your computer and keeps your download list and settings locally. It sends no telemetry and does not check for updates automatically.
- Clipboard monitoring is off by default. If you turn on **Offer copied links**, the app reads the clipboard to offer downloads, skips content marked private by password managers, and waits for you to accept before adding anything.
- Notifications are delivered through Windows. You can turn them off in Settings.
- The command-line tool talks to the running app through a local named pipe; this does not send your download list to a Boltget server.
- Uninstalling can remove the app's saved data if you select that option. Files you downloaded stay on your disk.

## The browser extension (coming soon)

The extension for Chrome, Edge and Firefox is built and will reach the browser stores soon. This is how it handles your data:

- It talks only to the Boltget app on your own computer, through the browser's native messaging. It has no server of its own, sends no telemetry, shows no ads and loads no remote code.
- When it hands a download to the app, it sends what the app needs to fetch the same file: the link, the file name and size the browser reported, the page it came from, and, if you granted site access, the cookies for that link and a short list of request headers (such as the browser's user agent and the referring page). Nothing else from the page is read.
- Site access is optional and asked for with an explanation. Without it the extension still hands downloads over, just without cookies, so downloads that need you to be signed in may stay in the browser.
- Cookies passed to the app are kept in memory only and are not written to your download list.
- Your capture settings and site lists are stored in the browser's own extension storage.
- If the app is not running, refuses a download or does not answer, the browser keeps the download as it normally would.
