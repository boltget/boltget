# AGENTS.md

Instructions for AI coding agents (and a quick reference for humans) working in this repository. Keep this file short; details live in `docs/`.

## Project

Boltget is a free, open-source (GPL-3.0-or-later) download manager that aims to match and beat IDM. Windows first, macOS and Linux later. Everything (code, UI, docs) is in English.

Current stage: v0.1 (Rust engine and CLI) is released; next is v0.2, the desktop app. See [docs/ROADMAP.md](docs/ROADMAP.md).

## Layout

| Path | What |
|---|---|
| `crates/engine` | `boltget-engine` library: probing, segmentation, I/O, persistence |
| `crates/ipc` | `boltget-ipc`: the named pipe (a Unix socket elsewhere) between the engine's owner (the app) and its clients (the CLI): framing, messages, server and client |
| `crates/cli` | `boltget-cli` package, `boltget` binary |
| `crates/native-host` | `boltget-native-host`: the binary browsers start for the extension (stdio native messaging relayed to the app's pipe) and its registration with the browsers. The protocol is `crates/ipc/src/browser.rs` |
| `crates/testserver` | `boltget-testserver`: local HTTP server that simulates misbehaving servers for tests |
| `fuzz/` | cargo-fuzz targets (own workspace, nightly; run in `.github/workflows/nightly.yml`). Logic and properties live in `crates/engine/src/fuzzing.rs`; the seed corpus runs in `cargo test` |
| `apps/web` | `@boltget/web`: boltget.app, Astro + Svelte hero island + Starlight docs ([docs/WEBSITE.md](docs/WEBSITE.md)). Copy in `src/i18n/en.json` and content collections; reads `brand/`, `CHANGELOG.md` and `bench/results/` at build time |
| `brand/` | Logo, icons, social images, tokens. Generated by `brand/scripts/build.mjs`; edit the script, not the outputs |
| `apps/extension` | `@boltget/extension`: the browser extension, WXT + Manifest V3 + Svelte 5, Chrome/Edge and Firefox builds ([docs/BROWSER-INTEGRATION.md](docs/BROWSER-INTEGRATION.md)). Pure logic in `lib/` (Vitest), Playwright tests with a stub host in `e2e/` |
| `apps/desktop` | `@boltget/desktop`: the Tauri 2 + Svelte 5 app ([docs/APP-DESIGN.md](docs/APP-DESIGN.md)). `src-tauri/` is the `boltget-desktop` crate (a Cargo workspace member, binary `Boltget.exe`) |
| `packages/native-messaging` | `@boltget/native-messaging`: the extension protocol's TypeScript types (generated; `pnpm --filter @boltget/native-messaging generate`, a Rust test fails while stale) and `extensions.json`, the one place the extension ids live |
| `packages/ui` | `@boltget/ui`: app design tokens (generated from `brand/tokens/tokens.json` by `scripts/generate.mjs`; run `pnpm --filter @boltget/ui generate` after changing the tokens or `src/messages/en.json`), fonts, the string catalog with `t()`, Svelte primitives |
| `docs/` | Design docs |

## Specs come first

- [docs/ENGINE.md](docs/ENGINE.md) is the authoritative engine spec; [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) covers process model, data model and security. Read the relevant section before changing engine behaviour.
- If you deviate from a doc or make a decision it leaves open, write that back into the doc in the same commit series. Docs and code must not disagree.
- User-visible changes get an entry under `Unreleased` in [CHANGELOG.md](CHANGELOG.md).

## Commands

Run all three before every commit you consider done:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Run the CLI: `cargo run -p boltget-cli -- get <url>` (add `--release` for any speed measurement).

Desktop app: `pnpm install`, then `pnpm --filter @boltget/desktop tauri dev` (the UI alone in a browser: `pnpm --filter @boltget/desktop dev`). Before committing app or UI changes run `check`, `lint` and `test` for both `@boltget/ui` and `@boltget/desktop` (`pnpm --filter <name> <script>`). After changing a Tauri command or an IPC type, regenerate `apps/desktop/src/lib/bindings.ts` with `pnpm --filter @boltget/desktop bindings` (a test fails while it is stale). In debug builds `BOLTGET_DEV_THEME=light|dark` forces a theme and `Ctrl+Shift+L` flips it.

Browser extension: `pnpm --filter @boltget/extension build:dev` (or `build:firefox:dev`), then load `apps/extension/.output/chrome-mv3-dev` unpacked; register the development host with `target\debug\boltget-native-host.exe --register` ([docs/BROWSER-INTEGRATION.md, Development](docs/BROWSER-INTEGRATION.md#development)). Before committing extension changes run its `check`, `lint`, `test` and `e2e` (`e2e` registers a stub host in HKCU and removes it again).

Website (pnpm workspace at the root, Node from `.node-version`): `pnpm install`, then `pnpm --filter @boltget/web dev`; before committing site changes run `pnpm --filter @boltget/web check` and `pnpm --filter @boltget/web build`.

## Rust rules

- Toolchain: stable via `rust-toolchain.toml`, edition 2024. Workspace lints (pedantic-lite clippy) are in the root `Cargo.toml`; don't relax them crate-wide, use a targeted `#[expect(..., reason = "...")]`.
- `unsafe_code` is denied. The only exceptions are `crates/engine/src/platform/windows.rs`, `crates/ipc/src/platform/windows.rs` (the pipe's ACL and session checks) and `apps/desktop/src-tauri/src/platform/windows.rs`, and every `unsafe` block there needs a `// SAFETY:` comment.
- Library code: errors via `thiserror`, no `unwrap()`/`expect()` on paths that can fail at runtime, rustdoc on public items. The CLI may use `anyhow`.
- Dependencies must be GPL-3.0-compatible and pass `cargo-deny` (`deny.toml`). Prefer pure-Rust crates that build on Windows without extra tools (this is why rustls uses the `ring` provider).

## Cross-platform pitfalls

- CI runs clippy and tests on **windows-latest and ubuntu-latest**. Code behind `#[cfg(windows)]` / `#[cfg(not(windows))]` is only linted on that platform, so lints like `unnecessary_wraps` on a Unix no-op can pass locally and fail CI. Review the other platform's branch by hand.
- Tests must not rely on Windows-only behaviour unless gated, and timing-based tests need generous timeouts: CI runners are slow and noisy.
- `cargo ... --workspace` includes the desktop app, which needs Tauri's system libraries on Linux (WebKitGTK; `ci.yml` installs them). Its Linux platform module is a set of no-ops that must keep compiling.

## Git

- Small, focused commits that each build and pass tests. Maintainers currently commit directly to `main`; everyone else opens a PR.
- Messages follow [Conventional Commits](CONTRIBUTING.md#commit-messages-conventional-commits): `feat(engine): ...`, `fix(cli): ...`, `test(engine): ...`, `docs(engine): ...`, `build: ...`, `ci: ...`. Imperative mood, first line at most 72 characters.
- No sign-off is required (the project does not use a DCO).
- Never force-push or rewrite history on `main`.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the full rules.
