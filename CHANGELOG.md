## [0.2.0-preview.1] - 2026-11-07

The first preview of the Boltget desktop app for Windows: the download list, the add sheet, the tray, notifications, settings, the command palette and queues, with the `boltget` command line working alongside it. It installs for your account with the Windows installer below. Previews are not code-signed and do not update themselves yet.

### Added

- The desktop app runs the download engine: it opens your downloads when it starts, streams their progress to the window several times a second in one batch for all of them, and continues downloads that were interrupted when the app was killed or the computer went down. Downloads you paused stay paused. While a `boltget` command-line download is using your downloads, the app waits and takes over when it finishes.
- The desktop app's download list: one calm row per download with its progress, speed and time left, grouped into Active, Queued and paused, and history by day, filtered by the sidebar's views and file-type categories and by search. Rows stay put while you work in the list. Select with the mouse or the keyboard (Shift and Ctrl work as in Explorer); Space pauses or resumes, Enter opens, Ctrl+Enter shows the file in its folder, Delete removes from the list with Undo, and Shift+Delete deletes the file after asking. Right-click for the same actions in a native menu, or switch to compact rows with Ctrl+Shift+D. It stays smooth with 500 downloads.
- The details pane (Ctrl+I) shows the selected download in depth: large live numbers, a file map that fills square by square as each connection writes, the speed over the last minute, the connections at work, where the file is saved, its link and checksum, and a speed limit for that download alone. A download whose link expired takes a fresh link right there; a failed one says what happened in plain words, with the technical details folded away.
- The add sheet: click Add download, press Ctrl+N or Ctrl+V, or drop a link on the window, and Boltget looks at the link before anything starts. It shows the file's name (edit it if you like), size, type, server and whether the download can resume, and says so calmly when the link is a web page, needs a sign-in, cannot be reached, is already in your list, would not fit on the drive, or would be saved under a new name because the file exists. Enter downloads. Choose the folder from the last three you used or the system's folder picker; "More options" sets connections, a speed limit, a checksum (a checksum the server sends is shown and checked anyway) and "Add paused". Paste several links, one per line, and they become a checklist with one folder for all.
- The desktop app lives in the tray: closing the window keeps your downloads going (it says so the first time), and the tray icon's pixel arrow lights up row by row while bytes are flowing, stays still when nothing moves or when Windows' animation effects are off, and tells you `3 active · 48.2 MiB/s · about 2 min left`. Its menu opens the app, adds links from the clipboard, pauses or resumes everything, sets a speed limit, opens your downloads folder and quits. The taskbar button shows the progress of what is downloading, yellow when it is paused and red when something needs you.
- Notifications: a completed download says how big it was and how long it took, with Open and Show in folder; a download that failed or whose link expired says why, with Fix…. Three or more finishing within a minute become one summary, and nothing pops up while you are looking at the window. Clicking one takes you to the download.
- One Boltget at a time: starting it again brings the window forward, and `Boltget.exe <link>` opens the add sheet with that link.
- Downloads that are running when you log off, restart or shut down are saved and continue when Boltget starts again.
- The `boltget` command line works together with the desktop app: while the app runs, `get`, `list`, `pause`, `resume`, `refresh`, `remove` and `config` go to it instead of stopping with "in use". `get` adds the download to the app and shows its progress in the terminal (Ctrl-C pauses it; `--detach` returns at once), `pause` reaches a download running anywhere, and several terminals can download at the same time. `--standalone` runs the download in the terminal's own process as before; a new exit code 10 means the app could not be reached or is from another release.
- Settings (Ctrl+,): theme (follow Windows, light or dark), start with Windows, keep running in the tray when the window closes, notifications, the download folder, categories with their own file types and folder, connections per download, the speed limit, and the proxy: none, the one Windows uses (Boltget follows changes to it) or one you type. Everything applies as you change it, and a value that cannot work says why right under it. Search Settings with Ctrl+F.
- The add sheet saves each file in its category's folder when you gave the category one, else in your download folder.
- Offer copied links (off until you turn it on): copy a link to a file in another app and Boltget offers to download it, quietly, without adding anything until you say so. The clipboard is read only while this is on, and never for what password managers mark private.
- The command palette (Ctrl+K) reaches every action, setting and download by typing a few letters, even a word that means the same ("throttle" finds the speed limits), and shows each action's shortcut. Settings lists all the keyboard shortcuts.
- Queues: every download waits its turn in a queue, Main unless you choose another, and a queue runs a set number of downloads at once (three to start with), starting the next one in line as soon as one finishes, fails or is paused. Make more queues with the + next to Queues in the sidebar; each shows how many downloads it holds. A queue's view is its order: drag downloads to a new place, or move the selection with Alt+↑, Alt+↓, Alt+Home and Alt+End, and drag downloads onto another queue in the sidebar to move them there. Stop a queue and its running downloads go back to waiting in their place; start it and they continue. A queue can start and stop on its own at a time of day, and put the computer to sleep or shut it down when it finishes, after 60 seconds you can cancel.
- Start later: choose a date and time in the add sheet ("More options") or with "Start later…" on any waiting or paused download, and it starts then, even if its queue is stopped. The Scheduled view lists them; a time that passed while Boltget was closed starts the download when Boltget opens.
- `boltget get --queue <name>` adds a download to a queue of the running app, where it waits for its turn while the terminal follows it. `boltget list` shows each download's queue and its place in line, and `--json` adds `queue`, `queue_name`, `queue_position` and `start_at`.
- A Windows installer for the desktop app: it installs Boltget for your account without administrator rights, with a Start menu entry, so notifications say "Boltget". Uninstalling removes everything it added, and your downloads list too if you tick "Delete the application data"; downloaded files always stay. Previews are not code-signed yet, so Windows SmartScreen may warn before it runs.
- `BOLTGET_DATA_DIR` now chooses where the desktop app keeps your downloads list in every build, as it does for the command line, so the app and a `boltget` started with the same variable work on the same list.

### Changed

- Easier to read and to use without a mouse: secondary text and the edges of text fields, drop-downs and checkboxes have more contrast in both themes; Tab moves around the window and inside dialogs without stopping on nothing; Settings starts with focus on its sections and Esc leaves it from anywhere but a text field; a screen reader hears each download's name and state, not its buttons; progress bars stay visible in Windows' contrast themes.
- While Boltget is hidden in the tray, its window gives back most of its memory (the working set drops from about 400 MiB to about 55 MiB).
- Quitting Boltget puts downloads that were running back in their place in their queue, so they continue when Boltget starts again (a queue you stopped keeps them waiting).
- `boltget list` now only reads your downloads, never opening them as their owner, so running it after Boltget was closed unexpectedly no longer stops the app from continuing those downloads when it starts again.
- The name is now written Boltget, with one capital, everywhere: the CLI's messages, the website, the logo and the documentation. Commands, paths and settings (`boltget`, `BOLTGET_DATA_DIR`) do not change.

### Fixed

- A very long file name that shortens to a name Windows reserves, such as `PRN` or `CON`, now gets a leading underscore like any other reserved name instead of slipping through. Found by the nightly fuzzer.

## [0.1.0] - 2026-10-31

The first release: the download engine and the `boltget` command-line downloader for Windows (a Linux build is included as a preview). There is no desktop app yet. The binaries are not code-signed until v1.0; how to verify them is in `docs/BUILDING.md`.

### Changed

- Faster on servers that limit the speed of each connection: the adaptive connection count reaches 16 connections in about 1.3 s (it took about 6 s before). On a local server limited to 2 MiB/s per connection, a 100 MiB download now takes 4.3 s instead of 6.8 s (8 fixed connections: 6.6 s; 16 fixed: 4.0 s). Boltget also remembers such a server for 24 hours, and the next download from it starts with the number of connections that paid off: a 10 MiB file from that server then takes 1.0 s instead of 1.4 s. Servers that do not reward more connections, and those that answer `429`/`503`, are handled as before.

### Added

- Downloads to exFAT and FAT32 USB drives and SD cards no longer stall on large files. These file systems cannot skip ahead in a file, so a connection that starts writing far into it makes Windows fill everything before it with zeros first, which could freeze a multi-gigabyte download for minutes. Boltget now keeps new connections within 64 MiB of the earliest missing byte there, so the file fills from the front and the pause is short. Drives that support sparse files (NTFS, ReFS) are unchanged.
- `--ca-cert FILE` (PEM or DER, repeatable) on `get`, `resume`, `refresh` and `bench` trusts extra root certificates on top of the system's trust store, for example a company CA that is not installed in Windows. Not saved: pass it again to `resume`.
- `boltget-testserver` can now serve HTTPS with HTTP/2 (`--tls`, or `--tls-port N` next to the plain port, `--alpn`, `--ca-out FILE` for its generated CA) and shape lab scenarios: added latency (`latency_ms=`) and a server-side connection limit (`conn_limit=`). New lab targets in `bench/targets.toml` cover 100 ms latency, a 4-connection limit and HTTP/2.
- `boltget bench`: measures download times on your own network. It runs each URL, or the targets in a TOML file such as `bench/targets.toml`, several times (`--runs`, `--warmup`), compares connection settings in rotating order (`-c auto,8`), checks size and SHA-256, and reports the median, interquartile range, min-max, MiB/s, time to first byte and tail time as a table, line-delimited JSON (`--json`) or CSV (`--csv`). Downloaded files are deleted after each run.
- A first benchmark against Internet Download Manager, with method, raw data and limitations: `docs/BENCHMARK.md`. The harness (`bench/`) includes a versioned target list, a PowerShell script that drives IDM and Boltget on the same files, and `boltget-testserver`, a local server for reproducible lab scenarios.

- The number of connections adapts: a download starts with 4 and adds connections only while they make it faster, reverts ones that do not, and halves when the server answers `429`/`503`, remembering that host's limit for 24 hours. `-c N` still fixes the count; `--max-connections` caps the adaptive one.
- Slow connections no longer hold up the end of a download: a slow connection's remaining bytes are split with an idle connection down to 64 KiB, and a stalled or very slow last connection is replaced within about a second.
- Speed limits: `--limit 5M` (also `500K`, `1048576`; `off` to remove) on `get`, `resume` and `refresh` limits one download and is saved with it; `boltget config set limit 5M` sets a global limit for all downloads, saved in the settings (`config get`, `config unset`, `config list`). Limits change without reconnecting.
- Checksums: `--checksum sha256:<hex>` (also `md5`, `sha1`, `sha512`, or just the hex) checks the finished file. Digests the server sends (`Repr-Digest`, `Digest`, `Content-MD5`, `Content-Digest`, `x-goog-hash`, `x-amz-checksum-sha256`) are checked too unless you pass `--no-server-digest`. The file is hashed while it downloads, so there is no long wait at the end. On a mismatch the file is not renamed, the download is marked `corrupt` and `boltget` exits with code 9; `boltget resume <id> --restart` downloads it again and `boltget resume <id> --no-checksum` keeps it.
- Expired links: a download whose link stops working (401/403/410, a login page instead of the file, or a redirect to an error elsewhere) waits as `needs_new_link` with its progress kept. `boltget refresh <id> <new-url>` continues it from a new link after checking that it is the same file (same size, and the same ETag or matching sample bytes); a link to a different file is refused with the reason.
- Proxies: `--proxy http://host:port`, `https://...` or `socks5://...` (with `user:password@` if needed), or the `http_proxy`, `https_proxy`, `all_proxy` and `no_proxy` environment variables; `--no-proxy` connects directly. Proxy passwords are never logged or saved.
- Cookies and logins: `--cookie-file cookies.txt` (Netscape format, as exported from browsers) sends each request only the cookies that match it, also across redirects, and cookies set by the server are kept for the download; `--cookie name=value` and `--user user:password` (HTTP Basic) are also available. Only the cookie file's path is saved; it is read again on `resume`.
- Downloads can be paused and resumed, and survive crashes. `boltget get` records every download under a numeric id; Ctrl-C pauses it (exit code 130) and `boltget resume <id>` continues where it stopped, even after the process was killed or the machine lost power. Progress is saved only once the bytes are on disk, so a resumed file is always byte-identical to the original. If the file changed on the server in the meantime, `resume` stops with a clear error instead of mixing two versions; `boltget resume <id> --restart` downloads it again.
- `boltget list [--json]` shows recorded downloads with their state and progress (it also works while another `boltget` is downloading), `boltget pause <id>` marks a download that is not running as paused, and `boltget remove <id> [--delete-file]` forgets a download and optionally deletes its file.
- The download database lives in `%LOCALAPPDATA%\Boltget` (Linux: `$XDG_DATA_HOME/boltget`); `--state <dir>` or `BOLTGET_DATA_DIR` choose another directory, and `boltget get --no-state` downloads without recording anything. `Authorization` headers are never saved: pass `-H` again to `resume`. Only one `boltget` at a time can use the database; a second one says so and exits with code 7. Exit code 8 means no such download, or the command does not apply to it (for example resuming a completed download).
- `--json` output: every line now carries the download `id`, a `resumed` event reports the progress a resume continues from, and a `paused` line ends a download stopped with Ctrl-C.
- `boltget get <url>`: a command-line downloader that splits a file across several connections (adaptive, or a fixed `-c N`) and keeps re-splitting the largest remaining part, so connections finish together. It shows a live progress bar with speed, ETA and a segment map, prints line-delimited JSON events with `--json`, and documents its exit codes in `boltget get --help`.
- Downloads recover on their own: retries with backoff, `Retry-After` respected, stalled or very slow connections reconnected, redirects followed, and expiring signed download links re-resolved from the original URL.
- Downloads stop instead of producing a corrupt file when the file changes on the server mid-download (ETag / Last-Modified checks on every request).
- File names come from `Content-Disposition` (including international names), are made safe for Windows, and never overwrite an existing file unless you pass `--overwrite`.
- On Windows, partial files are created sparse, so large downloads do not stall on disk preallocation. Completed files get the Mark of the Web, like browser downloads.
- Design documents: vision, features, architecture, engine specification, browser integration, video, tech stack, design principles, website, roadmap and release process (`docs/`).
- Project policies: GPL-3.0-or-later license, contributing guide, governance, support, security policy and code of conduct.
- GitHub configuration: issue forms, pull request template, code owners, Dependabot, label taxonomy, and workflows for PR title and documentation link checks.
